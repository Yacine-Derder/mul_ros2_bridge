# Protocol evidence

Inspected firmware Yacine-Derder/lps-node-firmware commit ea64edd9f84f0454dfa0b25bca59a9843aba04b9, `src/mul_log.c`, `src/mul_twr.c` (`rangeMetadata`, `logSuccess`, `mulTwrCancel`), `tools/mul_ranges.py` and `docs/mul_tdma.md` (codec6 section). See https://github.com/Yacine-Derder/lps-node-firmware/tree/ea64edd9f84f0454dfa0b25bca59a9843aba04b9 . No firmware code is vendored.

MR1 is ASCII, space-delimited key=value, newline terminated, at most 128 bytes including CRLF. Required fields: c uint32 decimal reference cycle; i/j uint8 decimal initiator/responder (0..254, distinct); l decimal emitting node, one endpoint; t exactly 10 hex digits local DW1000 timestamp; e 16 hex digits boot-local epoch; p 8 hex digits full-plan fingerprint; b decimal 1 AA or 4 FF; s 0 success or 1 failure; why lowercase/underscore reason. FF uses ascending endpoints. Successful records also require mm/raw uint32 decimal millimetres <=307475 and q 0/1 power compensation indicator; why=ok and nonzero epoch. Failure records omit all three numeric measurement fields. Zero distance is allowed; missing ranges are represented by has_range=false, never interpreted as a measured zero.

Both endpoints can emit AA and FF. Reporter is l, never the configured host ID. Successful marker is P1 TX for initiator, raw P2 RX for responder; failure marker is local failure time. DTU nominal frequency is 63897600000 Hz, modulus 2^40, but no conversion to ROS acquisition time is made. Epochs/time cannot be compared across radios. Epochs can repeat after full reboot. Capture session plus connection generation helps partition captures but cannot detect a reboot that leaves USB connected: operator/PC must segment full boots. Human MUL TWR lines, AA1, SL1, LOG and startup output have different semantics and are counted as unrelated, optionally raw logged; no incomplete MR1 is fabricated from them. AR does not emit geometry MR1. Quiet mode suppresses successes; firmware bounded queues may drop records. Silence does not mean success or a particular rate.

Local `serial_logs/serial_latest.log` (read only) contained 3 successes and 1 timeout from l=132, b=1, e=8, p=617AE520. Only these MR1 excerpts are authentic fixtures; follower and FF fixtures are synthetic formatter-conformant examples. Older October logs lack MR1. Local monitor/config scripts use 115200 baud (default, must verify on hardware). USB CDC line coding may be advisory. No port was opened. Firmware deployed version, per-node verbosity/plan, real follower output, actual rates, USB control-line behavior and timing accuracy remain physical checks.
