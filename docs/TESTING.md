# Offline testing

Run `./scripts/build_and_test.sh`. Both packages are compiled/installed with colcon, including generated C/C++/Python message support. Pytest is explicitly registered with colcon; `--return-code-on-test-failure` and `colcon test-result --verbose` prevent a zero-test success being mistaken for validation. Tests run on Cyclone DDS with domain 212 and localhost discovery. The GitHub workflow repeats this in a Jazzy ROS container (remote workflow status must be checked separately).

Coverage includes authentic reference MR1 excerpts; clearly labeled synthetic follower AA/FF initiator/responder, failure and changed plan/epoch records; missing/bad/unknown/duplicate fields; zero/max values; uint bounds and rollover markers; deterministic corrupt-byte fuzz; unrelated human/AA1/SL1/LOG traffic; chunk/newline assembly; oversized-buffer recovery; queue bounds and overflow counters; mismatched host/reporter retention; duplicate retention; disconnect/reconnect and partial-line reset; interruptible retry shutdown; rotating raw logs; generated message CDR serialization; actual rclpy PTY publication/status/diagnostics/staleness; retained status; rejected dynamic identity changes; all four installed launch processes with PTY sources and SIGINT cleanup; per-host config; acceptance result/field validation; shell syntax; deployment rendering idempotence.

`test/fixtures/reference.txt` consists only of four MR1 lines read from the local November 4 `serial_latest.log` (three successes, one timeout). `follower_synthetic.txt` is intentionally synthetic and includes AA responder and both FF reporter positions. No startup CPU serial, personal settings, credentials, generated logs, build or evidence files are committed. The firmware source/export validator was inspected read-only at the pinned commit in PROTOCOL.md.

For manual simulation (no hardware), run `python3 scripts/simulate_serial.py` in one terminal, then launch with the printed `/dev/pts/N` path in another terminal using domain 212/localhost. The simulator creates its own PTY and writes only that PTY master. Its repeated fixtures are not physical measurements. Ctrl-C closes it; the bridge should reconnect or become stale/disconnected as appropriate. Never label simulator captures as authentic hardware evidence.

Physical serial behavior, real follower output/rates, actual disconnect/reboot behavior, deployed firmware differences, cross-host DDS delivery, RF/range accuracy, USB control-line effects and PC estimation are deliberately unverified offline. Hardware acceptance is prepared for the operator and has not been run. The acceptance script's analysis and options are tested without invoking a real capture.

ROS references: [Jazzy custom interfaces](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Custom-ROS2-Interfaces.html), [Jazzy QoS](https://docs.ros.org/en/jazzy/Concepts/Intermediate/About-Quality-of-Service-Settings.html), [rclpy API](https://docs.ros.org/en/jazzy/p/rclpy/). Implementation was validated against the installed Jazzy APIs.
